# Workflow — Colaboração em Equipe e Desenvolvimento Compartilhado

## Objetivo

Orientar o agente durante atividades realizadas em equipe, garantindo organização, comunicação, respeito às responsabilidades dos integrantes e preservação do trabalho compartilhado.

## 1. Compreender a equipe e o projeto

Antes de iniciar:

- Identificar os integrantes envolvidos.
- Compreender a divisão de responsabilidades.
- Identificar as tecnologias e os repositórios utilizados.
- Consultar as regras de colaboração.
- Verificar o planejamento e o andamento das atividades.
- Identificar dependências entre integrantes.

Não presumir responsabilidades ou atribuir tarefas a pessoas sem informações suficientes.

## 2. Identificar o escopo de atuação

Antes de executar uma tarefa:

- Identificar o responsável pela atividade.
- Confirmar quais módulos podem ser modificados.
- Verificar restrições técnicas.
- Identificar dependências de outros integrantes.
- Respeitar os limites de atuação definidos para o agente.

Se uma tarefa ultrapassar o escopo autorizado, explicar a dependência e propor uma alternativa.

## 3. Consultar o estado compartilhado

Verificar, quando disponível:

- GitHub Issues.
- GitHub Projects.
- Backlog.
- Sprints.
- Pull Requests.
- Branches.
- Commits recentes.
- Documentação.
- Tarefas em andamento.

Evitar iniciar uma atividade que já esteja sendo executada por outro integrante sem verificar possíveis conflitos.

## 4. Planejar a execução

Para cada atividade:

1. Identificar o resultado esperado.
2. Definir o escopo.
3. Identificar os arquivos envolvidos.
4. Verificar dependências.
5. Identificar riscos de conflito.
6. Definir critérios de conclusão.
7. Estabelecer uma sequência de execução.

Dividir atividades grandes em entregas menores e verificáveis.

## 5. Trabalhar em paralelo com segurança

Quando houver atividades simultâneas:

- Identificar arquivos compartilhados.
- Evitar modificar os mesmos componentes sem coordenação.
- Definir contratos entre módulos.
- Respeitar interfaces e responsabilidades.
- Comunicar alterações que afetem outros integrantes.
- Integrar mudanças de maneira controlada.
- Verificar conflitos antes de consolidar alterações.

Não presumir que atividades paralelas são independentes.

## 6. Preservar o trabalho dos integrantes

Antes de modificar arquivos:

- Verificar o estado do Git.
- Identificar alterações não commitadas.
- Reconhecer arquivos modificados por outros integrantes.
- Preservar implementações existentes.
- Evitar sobrescrever trabalho compartilhado.
- Não descartar alterações sem autorização.

Nunca utilizar comandos destrutivos para resolver conflitos automaticamente.

## 7. Comunicação entre integrantes

Ao identificar uma dependência:

- Explicar o problema.
- Identificar o módulo envolvido.
- Descrever o que precisa ser fornecido.
- Especificar contratos ou informações necessárias.
- Indicar possíveis impactos no cronograma.

Manter a comunicação objetiva, técnica e respeitosa.

Não afirmar que uma pessoa realizou uma atividade sem evidências.

## 8. Gerenciar alterações compartilhadas

Antes de integrar mudanças:

- Revisar o diff.
- Verificar compatibilidade.
- Identificar conflitos.
- Avaliar dependências.
- Executar testes relevantes.
- Conferir se os critérios de aceitação foram atendidos.

Não integrar alterações incompletas ou incompatíveis sem comunicar os riscos.

## 9. Acompanhar atividades

Quando houver acesso às ferramentas de gerenciamento:

- Atualizar o andamento das tarefas somente com informações verificadas.
- Registrar bloqueios.
- Identificar dependências pendentes.
- Comunicar mudanças de escopo.
- Registrar entregas concluídas.
- Preservar o histórico das decisões.

Não marcar tarefas como concluídas apenas porque o código foi escrito.

## 10. Git e controle de versão

- Respeitar a estratégia de branches do projeto.
- Utilizar commits pequenos e descritivos.
- Revisar alterações antes de consolidá-las.
- Não sobrescrever commits de outros integrantes.
- Não realizar merge sem verificar compatibilidade.
- Não executar operações destrutivas sem autorização.
- Não realizar commit, push, merge ou publicação sem autorização explícita.

## 11. Documentar decisões

Registrar decisões relevantes sobre:

- Responsabilidades.
- Contratos entre módulos.
- Integrações.
- Dependências.
- Alterações arquiteturais.
- Divisão de tarefas.
- Resolução de conflitos.

Evitar depender exclusivamente de conversas informais para decisões técnicas importantes.

## 12. Relatório final

Apresentar:

- Atividade executada.
- Escopo respeitado.
- Arquivos modificados.
- Dependências identificadas.
- Integrações realizadas.
- Testes executados.
- Conflitos encontrados.
- Pendências.
- Próximos passos.

## Regras obrigatórias

1. Respeitar as responsabilidades dos integrantes.
2. Não sobrescrever trabalho de terceiros.
3. Verificar o estado do Git antes de modificar arquivos.
4. Comunicar dependências e bloqueios.
5. Não inventar informações sobre o andamento da equipe.
6. Preservar contratos entre módulos.
7. Não realizar operações destrutivas sem autorização.
8. Não executar ações externas sem autorização adequada.
9. Registrar decisões técnicas relevantes.
10. Priorizar colaboração, transparência e integridade do projeto.
